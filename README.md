# 我的 Web 学习项目

保留现有网页，每次围绕一个主题改进。先掌握原生 HTML、CSS、JavaScript，再考虑框架。

## 如何预览

可以直接用浏览器打开 `index.html` 查看页面。为了让本地存储等行为有稳定的运行环境，建议在编辑器中用本地静态服务器预览，并保持相同的地址和端口。

## 第 1 课：页面结构与可以退出的交互

### 三个文件分别做什么

- `index.html`：描述内容和含义，例如标题、段落、列表、按钮。
- `styles/styles.css`：决定内容的外观，例如字号、颜色、间距和宽度。
- `scripts/main.js`：响应用户操作，例如点击图片、更换姓名。

浏览器读取 HTML 后，会构建 DOM（一棵表示页面元素的树）。`document.querySelector("h1")` 就是在这棵树中寻找第一个一级标题，修改它的 `textContent` 会改变页面上显示的文字。

### 1. HTML 有明确的结构

```text
html
├── head：编码、页面标题、样式等配置
└── body：页面内容和本页脚本
    ├── main：本页的主要内容
    │   ├── h1、img、p、ul
    │   └── button
    └── script
```

原来的按钮和脚本写在 `</body>` 后面。浏览器通常会容错修复，所以页面可能仍能运行；能运行不代表源码结构正确。现在它们都放回 `body` 内。

`main` 表示主要内容，不会自动让页面变漂亮。HTML 标签描述含义，CSS 控制外观。

页面以中文交互为主，所以根元素使用 `lang="zh-CN"`，英文段落和列表单独标记 `lang="en"`。语言标记可以帮助朗读工具选择合适的发音。

脚本放在页面内容之后，是为了让执行 `querySelector` 时，前面的元素已经被解析。

### 2. 每次输入都可能有不同结果

`prompt()` 返回用户输入的字符串，点击取消时返回 `null`。

| 用户操作 | 返回值示例 | 现在的处理 |
| --- | --- | --- |
| 点击取消 | `null` | 结束函数，保留原状态 |
| 不输入就确定 | `""` | 结束函数，保留原状态 |
| 只输入空格 | `"   "` | 用 `trim()` 去除两端空格后，按空输入处理 |
| 输入姓名 | `" 小明 "` | 保存 `"小明"`，更新标题 |

原来的空输入分支会再次调用 `setUserName()`，这叫递归。取消也会触发它，因此用户无法正常退出这轮询问。现在用 `return` 提前结束本次函数调用。

注意检查顺序：先排除 `null`，再调用 `trim()`，因为 `null` 没有这个方法。

### 3. 显示与保存是两件事

- `myHeading.textContent = ...`：更新当前页面上的标题。
- `localStorage.setItem("name", myName)`：把姓名保存在当前浏览器、当前来源的本地存储中。
- 页面再次加载时，通过 `getItem("name")` 读取姓名，恢复标题。

本地存储不是服务器数据库，也不会自动在不同设备间同步。这个入门版本先假设浏览器允许本地存储，异常处理留到后续课程。

### 动手验证

1. 点击“设置 / 更换姓名”，输入 `小明`：标题应变成“欢迎你，小明！”。
2. 刷新页面：标题应保留姓名，页面不应自动弹窗。
3. 再次点击按钮并取消：弹窗关闭，标题保持原样。
4. 输入空格并确定：标题保持原样。
5. 输入两端带空格的新姓名：标题应使用去除两端空格后的姓名。

### 留给你的两个小练习

1. 将默认标题改成你自己的学习主页标题，预测已有存储姓名时刷新会显示什么，再实际验证。
2. 在控制台分别执行 `document.querySelector("h1").textContent` 和 `localStorage.getItem("name")`，观察“页面上的文本”和“保存的姓名”有什么区别。

## 后续学习路线

1. **CSS 盒模型和响应式**：理解内容、内边距、边框、外边距；解决固定 600px 宽度在手机上溢出的问题。
2. **语义化交互与表单**：用页面中的输入框替代弹窗，让图片切换也能通过键盘操作，并同步图片说明。
3. **JavaScript 状态管理**：整理选择元素、读取数据、更新页面和绑定事件的职责，处理存储失败。
4. **开发工具与网络基础**：使用开发者工具查看 DOM、调试事件、理解请求、路径与 HTTP。
5. **扩展为学习笔记页**：逐步实现新增、删除、筛选和保存笔记，再讨论是否需要框架。
